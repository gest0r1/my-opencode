## Ревью feature HEAD от 05.11.2026 — safety of reuse/leases

- **Reuse разрешён только при подтверждённых входах:** `gate-runner-cli.ts` сохраняет существующий `findReusableResults`, но исключает из него `live_postgres.command_indexes` и `input_kind=deployed-service` как динамические ресурсные входы. Это относится и к межзапусковому PASS, и к fallback `snapshot.reused_by_impact`. Pure commands прежним образом допускают reuse. Вероятная прежняя ошибка: повтор мог пропустить live command и не создать новый attempt-owned контейнер при совпадении source/toolchain. Регрессионный сценарий в `gate-runner-cli.test.mjs`, **не выполнен полноценно**.
- **Crash/restart dispatch lease:** `dispatch-leases.mjs::readLeases` больше не объявляет отсутствие owner_pid доказательством завершения отправленной работы с `parent_session_id` или `child_session_id`. `pipeline-runtime.ts::checkWake` считает crash-window без child ID неизвестным, а не `idle`. Сохраняется прежнее удаление legacy lease без parent/child при мёртвом владельце и при `stage=completed`. Имеющийся `leaseConflict` сохраняет блокировку пересекающихся путей; разные lanes по-прежнему могут работать. Регрессия в `pipeline-runtime.test.mjs`, нативный полный прогон отсутствует.
- **Существующие владельцы сохранены:** один RUN gate runner, один `dispatch-leases` registry и один `stage-cli` источник статуса. Новых кешей/lock stores/счётчиков не введено. Нерешённое: child без sessionID после рестарта требует ручного или SDK-доказанного завершения; автоматическое удаление lease по timeout было бы небезопасным.
